# Design kit

## This profile

Production content lives in `../README.md`. The banner was removed at the owner's request.
Run `python scripts/render_design.py` from the repository root to regenerate the
desktop and mobile review boards. It uses the existing `gh` CLI and GitHub's
Markdown rendering endpoint; it does not modify a GitHub repository.

Serve the repository with `python -m http.server 8767 --bind 127.0.0.1` and open
`http://127.0.0.1:8767/design/walkthrough.html`. Boards approximate GitHub styles;
the actual profile page inherits GitHub's CSS. The production profile is static.
Player transitions belong only to the review experience. The renderer embeds a
real visit-counter snapshot in the offline boards; the README retains the live
external image. Regenerating previews requests that service and may affect its count.

Generated boards, research captures/data, video, and evidence are intentionally
ignored by Git. Regenerate captures with the URLs and buckets in
`research/analysis.json`, then run `design-kit research .`. The scripts below
run from the repository root. See `../DESIGN.md` for the approved contract.

A vendor-free, repo-native design medium: HTML boards that share one token file, a
playable end-to-end walkthrough, a research dossier built from measured captures,
and an MP4 export. It works in any agent harness and any browser, and needs no build step.

```text
design/
├── tokens.css          # type, color roles (dark + light), space, radii, motion, reduced motion
├── board.js            # ?theme=dark|light for every board
├── boards/*.html       # one fixed-size board per screen or state
├── scenes.js           # the journey: chapter, title, caption, board, w, h, dur, scroll
├── walkthrough.html    # autoplay player (+ walkthrough.js)
├── index.html          # canvas overview: every board by theme and chapter
└── research/
    ├── captures/       # design-kit extract output: <slug>.json + light/dark screenshots
    ├── analysis.json   # comparables, principles, matrices, token evidence, decisions
    ├── data.js         # generated by design-kit research
    └── index.html      # the dossier (+ research.js); ?section=typography|color|motion|...
```

## Loop

1. `design-kit init` copies the kit into `design/` and never overwrites existing files.
2. Research: run `design-kit extract <public-url> --name <product> --bucket direct|adjacent|platform` for each comparable, then fill `research/analysis.json`.
3. Set every `tokens.css` value from research, citing the evidence in `analysis.json` `tokens`.
4. Build the boards: fixed size, tokens only, real controls, motion classes (`rise d1…d5`, `sheet`, `value`, `live`).
5. Write the journey in `scenes.js`. Keep strict JSON after the `=`.
6. `design-kit check` must pass; use `--strict` before approval.
7. `design-kit serve` to review in a browser, and `design-kit record` for the feedback MP4.

## Board contract

- The root element has a fixed width and height equal to its `scenes.js` entry.
- Colors, type, space and motion come only from `tokens.css`; no raw hex values in boards.
- Use real `<button>`, `<a href>`, `<input>` and `<label>` elements, visible focus, and touch targets of at least 44px.
- Use representative copy and data, including long, empty and error cases. No lorem ipsum.
- Every animation uses a named token and has a purpose (entry order, causality, state, live feedback).
